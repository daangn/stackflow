# Snapshot 저장 계약을 비동기로 통일

Snapshot 저장소의 쓰기 함수는 저장 매체의 실제 동기성에 관계없이 항상 `Promise<void>`를 반환하며, 저장소는 호출된 순서대로 쓰기 작업을 처리해야 한다. [동기 또는 비동기로 완료될 수 있는 혼합 계약](https://blog.izs.me/2013/08/designing-apis-for-asynchrony/)이 제어 흐름과 오류 관찰 시점을 불명확하게 만드는 것을 피하고, 플러그인은 저장소가 보장한 순서에 의존해 가장 최근에 요청한 Snapshot이 마지막에 남는다고 해석한다.
